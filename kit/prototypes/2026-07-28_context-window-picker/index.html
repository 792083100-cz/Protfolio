原型 上下文窗口与压缩阈值配置（步骤一·二）
2026-07-28 · Model Picker · v1.3.0
需求背景
平台需要支持配置上下文窗口与压缩阈值。作为切入点，Claude Sonnet 4.6 与 GPT-5.5 已具备 190K / 1M 两档上下文规格，需要在模型选择器上向用户暴露该切换能力。
痛点
当前模型选择器无法配置模型自身参数，190K 与 1M 属于同一模型的两种规格档位，若以两个独立条目展示会污染列表，用户也难以理解「哪个是哪个」。
解决方案
复用 v1.1.0 Auto 积分档位的 Tab 样式，在 Claude Sonnet 4.6 / GPT-5.5 的二级详情面板底部新增「上下文窗口」Tab（190K / 1M），Tab 切换仅影响面板内部，不修改一级面板模型行外显。
本次改动
  • 在 Claude Sonnet 4.6、GPT-5.5 的 .mf-model-detail 底部新增 .mf-model-detail__tier-divider + 上下文窗口 Tab 行（复用 .mf-model-detail__tier-*，无新增组件类）
  • Tab 文案：190K（默认）/ 1M，仅表达窗口容量，不含倍率标签（上下文窗口不影响积分消耗倍率）
  • Tab 切换仅影响二级面板内部选中态，不修改一级面板对应行 .mf-model-picker__meta（避免消耗一级面板横向空间）
  • 其他模型（Gemini / DeepSeek / Qwen / GLM）二级面板保持原状，不引入 Tab
  • 交互演示：点击 Chat Input 的「GPT-5.5」按钮唤起·收起 Picker（带弹出动效）；切换「上下文窗口」Tab 时，上下文按钮 tooltip 同步更新；步骤三（压缩阈值配置）待后续描述

上下文窗口切换 — 变体原型

Claude Sonnet 4.6 与 GPT-5.5 的二级详情面板底部新增「上下文窗口」Tab（190K / 1M）。Tab 切换仅作用于面板内部，不在一级面板模型行外显档位后缀，保持一级面板组件空间不受影响。上下文窗口不影响积分消耗倍率。

Detail Panel 变体 — Claude Sonnet 4.6（190K vs 1M）
左为 190K（默认），右为 1M。分割线在「可用能力」区之后，上下文窗口行在其下方。窗口档位不影响积分消耗倍率，故 Tab 中不展示倍率标签。
